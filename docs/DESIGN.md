# cccalendar 方案设计

> 状态：需求与技术基线已确认  
> 最后更新：2026-08-17  
> 当前阶段：P0-P14 已完成并通过验证；联网协作方案已确认，按 P15 逐步实现

## 1. 产品定位

cccalendar 是面向个人项目工作的 Windows 桌面日历与任务工作台。它把桌面日历、日程、待办、项目记录、提醒、AI 助手和常用时间工具整合在一个本地优先的应用中。

核心目标：

1. 用户无需打开主窗口，也能在桌面查看本周/本月、日程和待办。
2. 日程、待办、时间块、项目记录之间可以关联，但各自语义清晰。
3. AI 通过受控工具调用帮助查询和创建内容，不能绕过确认直接修改关键数据。
4. 数据首先可靠地保存在本机，并为未来跨电脑同步保留兼容的数据结构。
5. Windows 原生能力可按需启用，不强行替换系统任务栏时钟。

## 2. 已确认约束

- 目标平台：Windows，当前按单显示器设计。
- 桌面组件：可组合或拆分，可显示本周或本月。
- 工作日：周一至周五；默认工作时间为 08:00-12:00、14:00-17:30。
- 午休和下班后默认不由 AI 自动安排任务；需要时先询问。
- 同一时间允许重叠日程或时间块，但新增前必须提示冲突。
- 每周从周一开始。
- 需要中国农历、法定节假日、调休、节气和周数。
- AI 不需要语音输入。
- 跨电脑联网协作按 `docs/SYNC_DESIGN.md` 实施；首个垂直切片是团队会议室预约，个人数据同步后置。

## 3. 用户体验结构

### 3.1 桌面工作台

桌面工作台使用日历、日程、待办三个独立组件。默认只显示日历，日程和待办由用户按需显示；三者的信息结构为：

```text
+--------------------------+------------------+
| 本周/本月日历            | 所选日期的日程   |
| 日期、农历、节假日       | 时间、项目、提醒 |
| 项目色点、跨天色带       +------------------+
| 每格最多显示 3 项         | 今日/所选日待办  |
| 其余内容显示“还有 N 项”  | 四象限与完成状态 |
+--------------------------+------------------+
```

三个组件可以分别隐藏、移动和调整宽高。组件需要支持：

- 自由移动、缩放、吸附和布局记忆。
- 锁定位置但保留交互。
- 鼠标穿透，并可通过托盘菜单或全局快捷键恢复。
- 置于桌面底层、普通层级、始终置顶。
- 贴边隐藏和临时隐藏。
- 本周/本月切换，并分别记忆尺寸。
- 主日历点击日期或桌面工作台双击日期可按指定日期和起止时间新增日程。
- 日历格最多显示 3 项日程，超出后显示“还有 N 项”；新增后所有已打开窗口即时刷新。
- 可配置启动时隐藏主窗口，仅保留桌面组件和系统托盘。
- 任一组件右键菜单可勾选日历、日程和待办的显隐，选择跨重启保留。
- 三个组件分别记忆位置和宽高；背景不透明度允许 0–100%。
- 桌面日历组件的纵向位置固定在当前水平带内，拖动只允许调整横向位置；宽高仍可独立调整并记忆。
- 日历默认锚定屏幕顶部中央，右键可取消固定或启用顶部自动隐藏；隐藏时保留 4px 感应条，鼠标移入后展开。
- 每个组件右下角提供可见缩放手柄，右键“设置宽高”可直接输入像素尺寸。
- 日程组件显示本地起止时间或“全天”；窄宽下标题自动换行，列表不产生横向滚动。

### 3.2 右下角快速面板

通过系统托盘图标或可配置全局快捷键打开，不替换 Windows 原生任务栏时钟。

面板包含：

- 当前时间、日期、农历和天气。
- 迷你月历、今日日程和今日待办。
- 快速新增日程、待办、记录和项目。
- AI 快速输入框。
- 工具快捷入口。

会议室时间视图支持将腾讯会议邀请粘贴到输入框后手动导入（Enter 或“导入”），原始邀请随该日期日程保存至会议发生后第七天，并在第八天首次加载数据时自动清理。已导入的当天会议可从日期栏导出；导出窗口按会议分面板，支持单会议或全部会议复制，并可选择复制完整邀请或仅复制会议号和入会链接。占用块悬停显示主题、会议室和时间，双击打开详情。

### 3.3 主窗口

主导航：

1. 今天
2. 日历：月、周、日程表
3. 项目：概览、看板、甘特图、里程碑、记录
4. 待办：四象限、看板、列表
5. 记录：工作日志、会议记录、需求变更、问题记录
6. AI 助手
7. 统计
8. 工具中心
9. 设置

## 4. 核心领域设计

### 4.1 项目

项目包含名称、说明、颜色、状态、开始/截止日期、里程碑、参与人、进度和归档状态。项目进度可以由任务完成度计算，也允许手动覆盖。项目支持甘特图及任务依赖关系。

### 4.2 日程与时间块

- 日程具有明确的开始和结束时间，可为全天或跨天。
- 快速新增可创建不指定时间的单日全天日程；删除日程采用软删除并进入回收站，主窗口和桌面组件同步刷新。
- 时间块把待办安排进具体工作时间，但不改变待办本身的完成语义。
- 日程和时间块允许重叠；系统先展示冲突，再由用户选择保留重叠、寻找空闲时间或修改。
- 重复规则支持每天、工作日、每周、每月、每年和自定义间隔。
- 重复实例可修改仅此项、此项及以后或整个系列。
- 高级重复规则支持结束条件与跳过法定节假日。

### 4.3 待办

待办支持项目归属、开始/截止时间、子任务、标签、附件、重复、提醒、进度和依赖关系。

主要组织方式：

- 四象限：重要紧急、重要不紧急、不重要紧急、不重要不紧急。
- 看板：收集箱、待开始、进行中、已阻塞、已完成。
- 列表和日历。

“是否重要”由用户设置。“是否紧急”可依据截止时间自动计算并允许手动覆盖。拖动任务到其他象限时同步修改对应属性。

### 4.4 记录

记录类型包括工作日志、会议记录、需求变更和问题记录。编辑器使用富文本界面，支持 Markdown 快捷输入、图片、附件、关联项目、全文搜索、自动保存和历史版本。记录可以导出为 Markdown 和 PDF。

### 4.5 数据保护

- 删除内容进入回收站，默认保留 30 天。
- 本地数据库定时备份，提供手动备份、恢复和导入导出。
- 支持 ICS 文件导入导出。
- 后续支持只读 ICS URL 订阅、独立颜色和定时刷新。
- 附件由应用管理，数据库只保存元数据和稳定引用。

## 5. AI 助手

AI 同时支持兼容 OpenAI 接口的在线模型和 Ollama 本地模型。在线密钥必须保存在 Windows 凭据管理器，不写入普通配置或日志。

AI 能力：

- 查询日程、待办、项目和记录。
- 从自然语言创建日程、待办、时间块和记录。
- 拆分任务、检测冲突、寻找空闲时间。
- 总结会议与项目进展，生成每日计划和周报草稿。
- 把确认后的结论写入工作日志或需求变更。
- 助手输出按 Markdown 渲染标题、强调、列表和代码；用户消息保持纯文本，不执行模型返回的 HTML。
- 助手可附加 `.txt`、`.md`、`.csv`、`.json`、`.ics` 文本文件，最多 5 个、单个 1 MB、合计 2 MB；附件正文只进入下一次模型请求，成功后清空，失败时保留以便重试。

AI 附件用于分析和提取日程信息，不绕过预览确认直接写入数据库；需要直接导入标准日历文件时，仍使用日历页的 ICS 导入入口。

安全边界：

1. 查询和总结可以直接执行。
2. 新建操作默认展示结构化预览，用户确认后执行；设置可允许自动新建。
3. 修改、移动、批量操作和删除必须展示变更并确认。
4. 所有写操作记录审计日志，并支持撤销。
5. 默认只向模型提供完成当前请求所需的最小上下文。
6. LLM 只能调用应用提供的受控工具，不能直接访问数据库。

## 6. 提醒与计划

提醒采用全局默认值与单项覆盖：

- Windows 系统通知、桌面弹窗、声音和托盘标记。
- 自定义提前时间、重复催办和稍后提醒。
- 勿扰时段和开机后补发错过的提醒。
- 后台提醒服务不依赖主窗口保持打开。

AI 排期只使用默认工作时段。午休、下班后和加班时间需要用户明确允许。

## 7. 天气、外观与辅助工具

天气默认自动定位，失败时允许手动选择城市。城市搜索只展示城市级行政地点，支持 Enter 搜索并自动展开候选；中国城市和省级行政区统一显示法定全称。小时天气从当前整点开始，随后显示“现在”实况和未来小时，覆盖连续 24 个小时槽，不展示已经过去的小时。快速面板展示当前天气，详情展示逐小时和未来 7 天预报。

主程序支持浅色、深色和跟随系统。每个桌面组件可独立设置主题、透明度、圆角、缩放、字体、密度、云母/亚克力效果及日期、农历、节假日、调休、分割线等细分颜色。

应用图标采用蓝色日历页与绿色勾选的扁平标记：蓝色延续主界面强调色，日历表示时间规划，勾选同时表达日程与待办完成。图标保留透明外边缘，并提供 16-256px Windows ICO、1024px PNG 和可编辑 SVG 母版。

工具中心范围：

- 倒计时、番茄钟、时间进度、日期计算、世界时钟。
- 整点报时和久坐提醒。
- 区域/窗口/全屏/长截图、标注、马赛克、OCR 和截图贴屏。
- 任意窗口置顶和图片贴屏。
- 文本、图片和文件剪贴板历史、搜索、收藏及未来的加密跨电脑同步。
- 所有适用功能均提供可配置全局快捷键，并检测快捷键冲突。

统计包括项目完成率、逾期任务、每日专注时长、番茄钟统计和周报图表。

## 8. 逻辑架构

技术栈尚未确认，但实现必须保持以下边界：

```text
UI（主窗口/快速面板/桌面组件）
                |
应用服务（用例、权限、撤销、冲突检查）
                |
领域模型（日程、待办、项目、重复规则）
                |
基础设施（SQLite、Windows API、天气、LLM、未来同步）
```

- UI 不直接读写数据库。
- 领域层不依赖窗口框架、网络服务或具体数据库。
- LLM、天气、定位和未来同步都通过接口适配，测试中使用本地替身。
- 所有时间计算使用明确的时区；持久化保存标准时间和原始时区信息。
- 数据项从首版开始包含 UUID、创建/修改时间、版本、设备标识和删除标记，为后续同步做准备。

## 9. 技术决策

采用 .NET 10 LTS、WPF、SQLite/EF Core 和 xUnit，主支持 Windows 11 x64。代码组织为 Core、Infrastructure、Desktop 三个生产项目，先保持模块化单体，不为未实现功能预建框架。

完整决策、替代方案与依赖边界见 `docs/adr/0001-technology-stack.md`。视觉和交互约束见 `docs/UI_DESIGN.md`。

## 10. TDD 开发规则

每个可观察行为遵循 Red-Green-Refactor：

1. Red：先写最小失败测试，记录测试命令和预期失败原因。
2. Green：只实现使该测试通过的最小代码。
3. Refactor：在测试持续通过的前提下消除本次改动造成的重复。
4. Verify：运行相关测试；共享领域或持久化变更还需运行完整测试集。
5. Update：立即更新根目录 `WORKLIST.md` 的状态、验证结果和下一个任务。

测试层次：

- 领域单元测试：日期、重复规则、四象限、冲突和状态转换。
- 应用服务测试：创建/修改/撤销、AI 工具权限、导入导出和提醒调度。
- 基础设施集成测试：SQLite 迁移、文件、Windows 适配器和外部服务适配器。
- UI 测试：关键工作流和桌面窗口行为；视觉功能需要桌面截图核验。
- 端到端测试：快速新增、提醒、AI 预览确认、备份恢复等核心路径。

## 11. 完成定义

一个 work item 只有同时满足以下条件才能标记完成：

- 验收标准已通过自动化测试或明确的人工验证。
- 相关测试全部通过，且没有已知回归。
- 未引入超出该 work item 的功能或无关重构。
- 用户可见行为已记录在设计或使用说明中。
- `WORKLIST.md` 已同步状态、验证证据、遗留问题和唯一下一步。

## 12. 交付阶段

### M1：可运行的本地核心

建立工程、测试、SQLite 迁移和应用外壳；完成项目、待办、日程的最小本地闭环。验收结果是应用可以创建、重启后读取并展示项目、待办和日程。暂不包含桌面组件、AI 和辅助工具。

### M2：规划工作台

完成今天、日历、四象限、看板、项目、记录、提醒和备份恢复。验收结果是无需 AI 即可管理日常项目工作。

### M3：Windows 桌面体验

完成托盘快速面板、桌面工作台、独立组件、窗口层级、快捷键和个性化。验收结果是主窗口关闭后仍可查看桌面内容并接收提醒。

### M4：AI、天气与日历交换

完成天气、ICS 导入导出、在线/本地模型、受控工具、预览确认、撤销和总结。验收结果是自然语言可以可靠生成经用户确认的结构化日程和待办。

### M5：工具中心

按独立垂直切片实现时间工具、专注统计、报时、久坐提醒、截图、OCR、贴屏、窗口置顶和本地剪贴板历史。

### M6：联网协作与跨电脑同步

方案已单独确认，见 `docs/SYNC_DESIGN.md`。实现从团队工作区、会议室目录和在线预约开始；账户、服务端、权限、实时通知和冲突处理必须通过接口隔离，不与本地 SQLite 核心耦合。
