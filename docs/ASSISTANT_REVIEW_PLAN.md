# AI 助理模块改进方案

## 目标

把 AI 助理从“能发起请求和生成提案”提升为可持续使用的日历工作流：

- 多轮会话真正共享上下文，同时受消息数量和隐私边界控制。
- 查询结果准确、可解释，尤其是日期范围、排序、地点和冲突对象。
- 请求取消、失败、空响应和提案确认失败都能恢复，不留下无状态消息。
- 附件校验和出网行为对用户可见，错误在界面内闭环处理。
- 保留当前“思考”折叠展示；不将其替换为工具活动摘要。后续只补充工具来源、时间范围和冲突详情。

## 范围与非目标

本轮只改助理模块及其直接测试，不重做 provider 抽象、不引入新的 UI 框架，也不改变现有写入必须确认、审计和撤销的安全边界。跨设备同步聊天、向量检索、语音和自动执行 agent 延后到独立阶段。

## 分阶段方案

### A. 正确性与恢复能力（当前阶段）

1. 修正重复提交：只阻止短时间内同一次提交的重复触发，允许用户再次提出相同问题。
2. 修正历史读取：保留时间戳重复消息和 `ThinkingText`，避免加载时改变对话语义。
3. 修正日程查询：全天事件按日期范围过滤，按开始时间排序，返回地点；每日计划正确覆盖跨多日定时事件。
4. 附件错误统一转为界面可显示的提示，保留失败发送时的附件以便重试。
5. 聊天历史采用临时文件写入后替换，损坏或保存失败提供可诊断信号。

### B. 上下文与可解释性

1. 扩展 AI 请求契约，携带当前会话的 user/assistant 消息，并在超限时按时间裁剪或摘要。
2. 发送前显示 provider、是否本地、附件数量和字节数；支持一次性“不保存历史”模式。
3. 工具结果附带数据范围、更新时间和实体定位；冲突面板显示具体冲突事件的标题、时间和地点。
4. 保留“思考”折叠块，但限制其持久化策略并允许用户关闭展示。

### C. UI 工作流与性能

1. 增加停止、重试、重新生成、编辑后重发和空响应状态。
2. 只有用户接近底部时才自动跟随新消息；解除 DataContext 事件订阅。
3. 长会话启用可控虚拟化，补齐键盘焦点、AutomationProperties 和 1366/1920 运行时截图验证。
4. 提案、冲突和附件区域显示加载/失败状态，避免异常冒泡到全局处理器。

## 验收标准

- 同一会话中重复问题可以再次发送；历史重启后消息、时间戳和思考文本保持不变。
- “今天/本周”查询不包含范围外全天事件，日程按时间排序并带地点。
- 不支持附件、超数量、超大小均显示中文提示，不触发未处理异常。
- 历史写入中断不会留下半截 JSON；损坏文件不会静默清空用户历史。
- 助理相关单元测试、`eng\\verify.cmd` 和发布前启动冒烟全部通过。
